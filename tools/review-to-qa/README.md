# 缺点转问答 · Review → Q&A

把 Alexa（Rufus）给的「买家主要抱怨」或者评论里的每条缺点，**单独**拆成 6 条针对性 Q&A：问题全部咬住这一个缺点，中文一页、英文一页，导出一个两 sheet 的 Excel。

打开 `index.html` 即可使用，零依赖、无构建。

## 它做什么

1. **贴入** Alexa 那段总结（英文中文都行），或者自己整理的缺点清单
2. **核对** 解析出来的缺点：分类、原文、正面率都能改，不想生成的取消勾选
3. **生成** 每条缺点单独调一次模型 → 6 条 Q&A，全部围绕这一条（不是一套通用话术套所有缺点）
4. **导出** `产品名-缺点问答-日期.xlsx`，Sheet1 中文问答，Sheet2 英文

举个实际效果：Alexa 说「坐垫偏硬、腰托偏硬、久坐不舒服」，生成的是

> Q：坐垫是不是很硬？坐久了会不会不舒服？
> A：坐垫初坐会偏挺括，这是为了提供稳定支撑。建议前几周搭配薄坐垫过渡……如果您习惯软沙发般的下陷感，可能需要一点时间调整预期。

而不是「这类问题能提前发现吗」「能退换吗」这种放之四海皆可的废话。六条会分别覆盖：软硬手感、久坐支撑、会不会塌陷、透气季节、适合什么体型、怎么调更舒服。

## 输入格式

最理想的是 Alexa 那种「分类 + 正面率 + 短横线要点」的格式：

```
Durability (24% positive):
- Some customers report cracking, seams coming undone, and the piston blowing out within six months
Stability (27% positive):
- Customers say the chair gets noisy, arms can loosen after a few months, and it can fall apart
```

中文同理：

```
耐用性（24% 正面）：
- 有买家反馈六个月内出现开裂、缝线开线、气压棒漏气
```

解析规则：

- 以 `分类（24% positive）:` 或 `分类（24% 正面）：` 结尾的行当作小节标题，括号里的百分比记为该缺点的正面率
- `-` `•` `*` `·` 开头的行当作缺点要点
- 没有小节的裸文本整段当作一条缺点，仍然可以手动改
- 正面率 **低于 50% 的默认勾选**，高于 50%（比如 `Value for money (57% positive)`）默认不生成——那是优点不是缺点
- 以 `Overall` / `总结` 开头的收尾句会被跳过
- 勾选「同一句里的多个问题拆开生成」，会把「开裂、缝线开线、气压棒失效」拆成三条，各自出 6 条

## API 设置

用的是 **DeepSeek**（OpenAI 兼容接口），在工具里填自己的 key：

| 项 | 默认值 | 说明 |
| --- | --- | --- |
| API Key | — | `sk-` 开头，只存本机 `localStorage`（键 `qaGen.cfg.v1`） |
| 接口地址 | `https://api.deepseek.com` | 换成其他 OpenAI 兼容服务也行，会自动拼 `/chat/completions` |
| 模型 | `deepseek-chat` | 按你的账号可用的模型填 |

- key 只在浏览器里，**不写进页面源码、不上传**，所以这个仓库是公开的也没关系
- 页面底部有「测试」按钮，能立刻确认 key、网络、接口地址通不通
- 浏览器直连 DeepSeek 是通的（`file://` 双击打开也能调，不需要起本地服务）
- 一条缺点约 1500–2500 tokens，按 DeepSeek 现在价格一条不到一分钱；跑完界面会显示本次消耗

## 生成规则（prompt 里写死的约束）

- 6 条 Q 必须是同一个缺点的不同侧面，不许跑题到物流、客服、退换、安装、价格
- Q 是犹豫买家的口吻，A 是卖家/客服在认真解释，不是宣传口号
- **不许编造材质、工艺、结构、参数、认证**（比如「透气面料」「承重 150kg」「TÜV 认证」）。模型不知道你的真实配置，编了就是隐患——所以你还是要自己过一遍，界面也有核对提醒
- 条数不足 6 条会自动重试一次，重试后仍不足会在分组标题上标「只回了 N 条」，可以单独重试

## 模板兜底

没有 key 或者不想联网时，点「模板兜底」：用内置的分类语料（8 类 × 6 组）拼出问答，6 个问题同样会咬住具体缺点。

质量比 AI 差一截，定位是「断网时也能出一版草稿」，建议逐条改。它是确定性模板，同一条缺点每次结果一样。

## 导出结构

`产品名-缺点问答-YYYYMMDD.xlsx`

| Sheet | 列 |
| --- | --- |
| 中文问答 | 序号 / 缺点分类 / 问题 Q / 回答 A |
| English | No. / Category / Question / Answer |

排版细节：表头深蓝底白字、冻结首行、自动筛选、细边框、单元格顶端对齐并缩进、按内容算行高（宁可多留白也不切字）、横向打印、中文表用微软雅黑、英文表用 Calibri。

xlsx 是页面里手写的最小 OOXML（ZIP 用 store 不压缩 + SpreadsheetML 的 `inlineStr`），没有引入任何 Excel 库。

## 技术

- 单文件 HTML（约 85 KB），样式和脚本全部内联，无第三方依赖、无 CDN、无构建
- 数据：输入与结果存 `localStorage`（`qaGen.v1`），API 配置存 `qaGen.cfg.v1`
- 一次调用生成一条缺点的 6 组问答，并发 3，失败/条数不足自动重试一次
