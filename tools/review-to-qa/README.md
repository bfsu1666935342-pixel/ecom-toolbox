# 缺点转问答 · Review → Q&A

把 Alexa（Rufus）给的「买家主要抱怨」或者评论里的缺点，每个拆成 **6 条 Q&A**，中文一页、英文一页，导出一个两 sheet 的 Excel。

打开 `index.html` 即可使用：纯静态、零依赖、离线、数据不出本机。

## 它做什么

1. **贴入** Alexa 那段总结（英文中文都行），或者自己整理的一段缺点清单
2. **核对** 自动解析出来的缺点：分类、原文、正面率都能改，不想生成的取消勾选
3. **生成** 每个缺点 6 条问答，Q 和 A 都可以逐条改
4. **导出** `产品名-缺点问答-日期.xlsx`，Sheet1 中文问答，Sheet2 英文

## 输入格式

最理想的是 Alexa 那种「分类 + 正面率 + 短横线要点」的格式：

```
Durability (24% positive):
- Some customers report cracking, seams coming undone, and the piston blowing out within six months
Stability (27% positive):
- Customers say the chair gets noisy, arms can loosen after a few months, and it can fall apart
```

中文同理：

```
耐用性（24% 正面）：
- 有买家反馈六个月内出现开裂、缝线开线、气压棒漏气
```

解析规则：

- 以 `分类（24% positive）:` 或 `分类（24% 正面）：` 结尾的行当作小节标题，括号里的百分比记为该缺点的正面率
- `-` `•` `*` `·` 开头的行当作缺点要点
- 没有小节的裸文本会整段当作一条缺点，仍然可以手动改
- 正面率 **低于 50% 的默认勾选**，高于 50%（比如 `Value for money (57% positive)`）默认不生成——那是优点不是缺点
- 以 `Overall` / `总结` 开头的收尾句会被跳过

## 6 条问答是怎么来的

不是 AI 生成，是一套固定角度 × 分类语料的模板引擎，所以能离线、结果稳定。每个缺点固定覆盖 6 个买家真正会问的角度：

| # | 角度 | 例子 |
| --- | --- | --- |
| 1 | 现象确认 | 「真的会开裂、缝线开线吗？」→ 会，但不是每台，附正面率 |
| 2 | 时间线 | 「一般用多久会出现？」→ 六个月内（从原文里抽时间） |
| 3 | 高强度使用 | 「每天坐 8 小时会更严重吗？」→ 按分类给不同答案 |
| 4 | 提前发现 / 避坑 | 给具体可执行的动作 |
| 5 | 售后 / 退换 | 哪些件在保修内、怎么处理 |
| 6 | 值不值得买 | 结论 + 什么情况该加预算 |

第 3、4、5、6 条按**缺点分类**取语料，第 1、2 条用**抽出来的具体问题词**拼。所以同一段 Alexa 文本里，「开裂 / 缝线开线 / 气压棒失效」会被识别成具体问题，而不是笼统地说「质量不好」。

### 分类

`耐用性 / 稳固性 / 坐感舒适 / 性价比 / 尺寸 / 安装 / 气味 / 其他`，共 8 类。分类决定第 3–6 条的答案，下拉框可以手动改。

### 问题词表

文件里的 `SYMPTOMS` 数组把评论里的说法映射成中英对照的具体问题，共 16 个：开裂、缝线开线、气压棒失效、表面脱皮、框架变形、左右摇晃、异响、螺丝松动、散架、坐垫偏硬、腰托偏硬、久坐不舒服、价格不值、安装麻烦、异味、尺寸不合适。

要加一个自己的问题，在 `SYMPTOMS` 里加一行即可：

```js
{key:'rust', cat:'durability', zh:'生锈', en:'rusting', re:/rust|corrode|生锈|锈/i},
```

`re` 是中英文都匹配的正则，`cat` 决定落到哪一类语料。同理，改 `CATS` 里对应分类的 `tipZh/tipEn/fixZh/fixEn/decideZh/decideEn` 就能换成自己的话术。

## 关于「离线」

能离线，是因为这个工具**不调用任何模型**：拆分靠正则和关键词表，写作靠模板加变量填充。代价是文案带模板味，适合当**初稿**——逐条改几句就可用，不适合指望它自己写出人味儿。

两个做不到的事，写清楚免得踩坑：

- **不能读图里的字（OCR）。** 浏览器离线做 OCR 要额外几十 MB 的模型，而且 `file://` 双击打开时 worker 和 wasm 会被安全策略拦住，跑不起来。所以截图只是拖进来当对照（支持粘贴和拖拽，不参与生成）；文字请从 Alexa 页面选中复制，或截图后用微信 / 系统截图工具取字。
- **不联网、不上传。** 没有网络请求，所有数据在 `localStorage`（键 `qaGen.v1`），换浏览器或清缓存会丢，导出的 xlsx 才是留存。

## 导出结构

`产品名-缺点问答-YYYYMMDD.xlsx`

| Sheet | 列 |
| --- | --- |
| 中文问答 | 序号 / 缺点分类 / 缺点原文 / Q（问题）/ A（回答） |
| English | No. / Category / Source / Question / Answer |

表头深色加粗、冻结首行、自动换行、按内容估算行高。xlsx 是页面里手写的最小 OOXML（zip 用 store 不压缩），没有引入任何 Excel 库。

## 技术

- 单文件 HTML（约 55 KB），样式、脚本全部内联，无第三方依赖、无 CDN、无构建
- Excel 导出：手写 ZIP（CRC32 + store）+ SpreadsheetML，`inlineStr` 存单元格
- 中文、英文各写一遍，不是机翻：同一份结构化数据（分类、问题词、时间、正面率）分别套中文和英文模板
