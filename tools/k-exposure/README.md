# 流量承接诊断 · Keyword Exposure

回答一个问题：**某个关键词的流量，是没打进来，还是打进来了没接住？**

导入「搜索词报告」和「搜索量词库」，工具会算出每个词的**曝光覆盖率 k** 和 **CTR**，然后给一句结论：去抢位置、改主图、查转化，还是加预算。

打开 `index.html` 就能用，纯本地计算，不上传任何数据。

## 两个输入

| 输入 | 从哪来 | 需要什么列 |
| --- | --- | --- |
| **搜索词报告** | 亚马逊广告后台 → 报表 → 搜索词报告（或领星/SIF 的搜索词分析） | 搜索词、曝光量、点击（花费、订单、销售额有则更好） |
| **搜索量词库** | 西柚 / SIF・卖家精灵 / ABA 搜索词表现，或本仓库另一个工具「广告结构反推」导出的词库 | 关键词 + 月搜索量（周数据会按覆盖天数折算） |

支持 `.xlsx` 和 `.csv`；词库可以多选，会自动合并（同词取最大值）。搜索词报告允许是**按日明细**，工具会先按词聚合再计算。

## 核心指标

```
k   = 报告期曝光 ÷ 报告期搜索次数      ← 曝光覆盖率（0.1 = 10 次搜索里有 1 次看到你）
CTR = 点击 ÷ 曝光                     ← 看到的人点不点
CVR = 订单 ÷ 点击                     ← 点进来的人买不买
```

`报告期搜索次数 = 月搜索量 × 报告天数 ÷ 30`。报告天数优先从文件名/表头里的日期区间自动识别，也可以手填。

**k 的含义**：`k=0.06` 表示这个词你只覆盖了 6% 的搜索；`k>1` 说明你在多个位置（SP + SB/SBV 或多活动）重复出现。

## 结论规则

| 条件 | 结论 | 该做什么 |
| --- | --- | --- |
| k < 0.1，且 CTR 或 CVR 明显高于平均 | 曝光少但效率好 | **优先加价**（性价比最高） |
| k < 0.1，CTR/CVR 一般 | 曝光不足 | 抢位置：提出价 / 加 Top of Search 溢价 |
| k ≥ 0.1，CTR < 账户平均 0.6 倍 | 曝光够、点不动 | 改主图 / 价格 / 评分 / 优惠 |
| CTR 正常，CVR < 账户平均 0.5 倍 | 点得进、不买 | 查详情页 / 变体库存 / 配送 |
| k ≥ 0.5，CTR 与 CVR 都不差 | 都好 | 加预算扩量 |
| 点击 < 20 | 样本不足 | 不下结论，先积累 |

判断阈值里的「平均」用的是**这份报告自己的加权平均**，不是行业基准——所以它比的是「这个词相对于你自己的其他词」。

## 为什么必须把 k 和 CTR 分开

只看 CTR 会把两种完全不同的问题混在一起：

- 曝光集中在页面底部 / 商品页 → CTR 天然低，但问题是**位置**
- 曝光已经铺满首页 → CTR 还低，问题才是**素材/价格**

k 低的时候不要判 CTR；k 上去了 CTR 还低，那才是真的接不住。

## 已知限制

- 搜索量来自第三方估算，不同厂商对同一个词能差 2 倍以上；**一次只用一家词库**，看相对值不要看绝对值
- 词库里没有的长尾词算不出 k：这些词只显示 CTR，标「待补搜索量」
- 搜索词报告里 ASIN/类目定投的行没有搜索量，会被同样标为待补
- 点击 < 20 的词，CTR 的统计噪声很大，工具会标「样本不足」

## 技术说明

- 纯 HTML + CSS + 原生 JavaScript，零依赖、无构建；xlsx 解析器与「广告结构反推」同一套（zip + `DecompressionStream` + XML）
- 所有计算在浏览器内存里完成，不写 `localStorage`、不发网络请求
- 单文件约 30 KB
